# 리소스 관리 시스템 요구사항 정의서

## 1. 프로젝트 개요

### 1.1 서비스 비전
사내에서 Google Sheets로 관리하던 리소스(리소스키, 메뉴, 기능)를 체계적으로 관리할 수 있는 웹 애플리케이션. 실수로 인한 데이터 손상 방지, 변경 이력 추적, 버전 관리 및 롤백 기능을 제공하여 안정적인 리소스 관리 환경을 구축한다.

### 1.2 핵심 가치 제안

**관리자 관점**
- 사용자 권한 관리를 통한 데이터 무결성 보장
- 버전 관리 및 롤백을 통한 안전한 변경 관리
- 신규 유저 승인 및 권한 부여 프로세스

**이용자 관점**
- 직관적인 UI로 리소스 수정, 추가, 삭제
- 드래그 앤 드롭 기반의 편리한 행 순서 변경 및 다중 선택
- TSV 형식의 import/export 지원

**기존 대비 개선점**
- 의도치 않은 셀 수정 방지 (권한 기반 접근 제어)
- 모든 변경에 대한 이력 관리 (누가, 언제, 무엇을 변경했는지)
- 버전 관리를 통한 안전한 롤백

---

## 2. 서비스 구성

### 2.1 주요 구성 요소
- **웹 프론트엔드**: 리소스 관리 UI (탭 기반, 테이블 형식)
- **백엔드 서버**: 인증/인가, 리소스 CRUD, 버전 관리, import/export 처리
- **데이터베이스**: 리소스 데이터, 사용자 정보, 변경 이력, 버전 정보 저장

### 2.2 리소스 종류
1. **기능 (Functions)** - functions.tsv
2. **메뉴 (Menus)** - menus.tsv
3. **리소스 키 (Message Resource)** - message-resource.tsv

---

## 3. 핵심 기능 요구사항

### 3.1 사용자 인증 및 권한 관리 (Authentication & Authorization)

#### 3.1.1 계정 관리
**목적**: 사용자 인증 및 역할 기반 접근 제어

**기능 요구사항**:
- **관리자 계정**:
  - 시스템 최초 구동 시 미리 정의된 관리자 계정 자동 생성
  - 관리자는 모든 리소스에 대한 읽기/쓰기 권한 보유
  - 사용자 권한 관리 가능
- **일반 사용자 계정**:
  - 회원가입을 통한 계정 생성
  - 가입 후 관리자의 권한 부여 대기 상태
  - 권한 종류: 읽기(조회만 가능), 쓰기(수정/추가/삭제 가능)

#### 3.1.2 신규 사용자 관리
**목적**: 관리자가 새로 가입한 사용자를 확인하고 권한을 부여

**기능 요구사항**:
- 관리자 전용 신규 가입자 확인 화면
- 가입자 목록 표시 (가입일시, 이름, 이메일 등)
- 권한 부여: 읽기, 쓰기 중 선택
- 권한 변경 이력 관리

### 3.2 리소스 관리 (Resource Management)

#### 3.2.1 공통 UI 구조
**목적**: 3개 리소스 탭에 동일한 형식의 관리 UI 제공

**기능 요구사항**:
- **탭 기반 네비게이션**: 기능, 메뉴, 리소스 키 탭
- **테이블 형식**: 각 리소스 종류에 맞는 컬럼 표시
- **공통 기능**:
  - 행 추가, 수정, 삭제
  - 다중 행 선택 (드래그 또는 Shift/Ctrl 클릭)
  - 선택한 행 일괄 삭제
  - 선택한 행 일괄 이동
  - 드래그 앤 드롭으로 행 순서 변경
  - 검색 및 필터링
  - 페이지네이션 또는 가상 스크롤

**UI/UX 요구사항**:
- 드래그 앤 드롭으로 행 순서 변경 (직관적 핸들 표시)
- 드래그로 연속 행 범위 선택
- 다중 선택 후 일괄 작업 (삭제, 이동) 지원
- 인라인 편집 또는 모달 편집 지원
- 변경 사항 시각적 표시 (수정된 셀 하이라이트)

### 3.3 Import/Export 기능

#### 3.3.1 TSV Export
**목적**: 리소스 데이터를 TSV 형식으로 내보내기

**기능 요구사항**:
- 각 리소스 탭에서 전체 또는 선택한 행을 TSV로 export
- 헤더 행 포함
- 파일명: functions.tsv, menus.tsv, message-resource.tsv
- UTF-8 인코딩

#### 3.3.2 TSV Import
**목적**: TSV 파일을 업로드하여 리소스 데이터 일괄 등록/갱신

**기능 요구사항**:
- TSV 파일 업로드
- 데이터 유효성 검증 (컬럼 수, 필수 필드 등)
- 미리보기 표시 (import 전 변경 사항 확인)
- 기존 데이터와의 충돌 처리 (덮어쓰기/건너뛰기 선택)
- import 결과 요약 (성공/실패 건수)

### 3.4 변경 이력 관리 (Audit Trail)

#### 3.4.1 변경 이력 기록
**목적**: 모든 리소스 변경에 대한 추적 가능한 이력 관리

**기능 요구사항**:
- 모든 수정, 추가, 삭제 작업 시 이력 자동 기록
- 기록 정보:
  - 변경 일시
  - 변경자 (사용자 정보)
  - 변경 대상 (리소스 종류, 해당 행)
  - 변경 유형 (추가/수정/삭제)
  - 변경 전 값
  - 변경 후 값
- 이력 조회 화면 (필터링: 날짜, 사용자, 리소스 종류)

---

### 3.5 버전 관리 (Versioning)

#### 3.5.1 버전 관리 방식
**목적**: 리소스 상태의 스냅샷을 저장하고 필요 시 롤백

**기능 요구사항**:
- **자동 버전 생성**: 사용자가 리소스를 수정할 때마다 자동으로 변경 이력(diff) 기록
- **명시적 버전 태깅**: 관리자가 특정 시점에 버전 이름(태그)을 부여하여 주요 릴리스 포인트 지정
- **버전 목록 조회**: 태깅된 버전 목록 및 각 버전 간 변경 내역 확인
- **롤백**: 관리자가 특정 태깅 버전으로 롤백 가능
- 롤백 시 확인 팝업 표시
- 롤백 자체도 이력으로 기록

**버전 관리 상세**:
- 개별 변경은 모두 이력으로 추적 (3.4 변경 이력)
- 관리자가 의미 있는 시점에 "v1.0", "2025-05 릴리스" 등 태그를 부여
- 롤백은 태깅된 버전 단위로만 가능 (안정성 보장)

## 4. MVP 개발 범위

### 핵심 기능 (필수)
**목표**: 기본적인 리소스 관리 프로세스 구현

**인증/권한**:
- 관리자 초기 계정 자동 생성
- 회원가입 및 로그인
- 관리자의 사용자 권한 관리 (읽기/쓰기)
- 신규 가입자 확인 화면

**리소스 관리**:
- 3개 리소스 탭 (기능, 메뉴, 리소스 키)
- 리소스 CRUD (추가, 조회, 수정, 삭제)
- 드래그 앤 드롭 행 순서 변경
- 다중 선택 및 일괄 작업

**Import/Export**:
- TSV export (전체/선택)
- TSV import (유효성 검증 포함)

**이력 및 버전**:
- 변경 이력 자동 기록 및 조회
- 관리자 버전 태깅
- 버전 롤백 (관리자 전용)

## 부록

### A. 용어 정의
- **리소스**: 시스템에서 관리하는 데이터 항목 (기능, 메뉴, 리소스 키)
- **TSV**: Tab-Separated Values (탭으로 구분된 값 형식)
- **롤백**: 특정 이전 버전의 상태로 되돌리는 작업
- **버전 태깅**: 특정 시점의 리소스 상태에 이름을 부여하는 작업
- **인라인 편집**: 테이블 셀을 직접 클릭하여 편집하는 방식

### B. TSV 파일 형식 참고
- 인코딩: UTF-8
- 구분자: 탭 문자 (`\t`)
- 헤더: 첫 번째 행은 `#`으로 시작하는 컬럼 헤더
- 각 리소스 종류별 파일: functions.tsv, menus.tsv, message-resource.tsv
